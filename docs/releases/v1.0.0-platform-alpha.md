# CareerOS v1.0.0 Platform Alpha

Release date: 2026-07-31

## Platform Vision

CareerOS addresses the fragmentation of professional data across formats and platforms. It provides a single canonical professional profile as the source of truth, deterministic analysis of that data, and portable, tailored career artifact generation. The reasoning layer eliminates hallucination and non-determinism from AI-generated career documents by computing analytical facts before any LLM interaction.

## Major Architectural Milestones

### Canonical Professional Profile

A JSON Schema (Draft 2020-12) canonical profile is the single source of truth for professional facts. All generated artifacts derive from it - nothing appears in an artifact that is not represented in the profile.

- 18 JSON Schema entity definitions (`schemas/*.schema.json`)
- Validator (`EntityValidator`) and schema loader with deterministic validation
- State-aware profile repository with `staging`, `canonical`, and `archived` profile states

### Acquisition Pipeline

Ingests source documents (DOCX) and constructs structured profile data for staged review.

- Document reading, optional LLM extraction, canonical profile construction, and YAML output
- Imported profiles land in `profiles/staging/` for review before promotion to canonical

### Deterministic Reasoning Engine

An in-process, deterministic rule engine computes analytical facts over the profile before any LLM interaction.

- 23 rules across experience, skill, and tenure domains
- Topological dependency ordering with validation
- `ReasoningFindings` (career stage, core competencies, strongest experience) attached to export contracts for generator consumption

### Professional Knowledge Platform Architecture

Layered, domain-driven architecture with explicit boundaries:

- **Schema Foundation** - entity definitions and validation rules
- **Acquisition Layer** - ingest, extract, normalize, validate
- **Knowledge Layer** - in-memory property graph built from the canonical profile
- **Reasoning Layer** - deterministic rules consuming the graph, producing findings
- **Generation Layer** - registries of generators consuming export contracts
- **Delivery Layer** - Typer CLI and FastAPI REST API
- **Optimization Layer** - JD-aware recommendation engine (26-concept taxonomy) with deterministic summary metrics

### Artifact Template Registry

Registry of reusable artifact templates that define how profile entities map into generated artifacts.

- 2 templates: `standard_cv`, `standard_interest_letter`
- Automatic artifact creation (`POST /profiles/{profile_id}/artifacts`)

### Tailored CV Generation

Job-description-aware CV generation through the `/generate/artifact` endpoint.

- Deterministic MarkdownCVGenerator (no JD) or LLM-powered tailoring when `CV_LLM_ENABLED=true` and a JD is provided
- ADD recommendations computed by the optimizer and surfaced via `X-Optimization-*` response headers
- Profile coverage, job match, and requirement metrics computed deterministically

### Interest Letter Generation

Interest letter generation routed through the same reasoning/optimization pipeline as CVs when a job description is provided, with optimization status, metrics, and recommendations returned to the frontend.

### Markdown and DOCX Generators

4 generator classes registered across Markdown and DOCX formats:

- `MarkdownCVGenerator`, `DocxCVGenerator`
- `MarkdownCoverLetterGenerator`, `DocxLetterGenerator` (cover and interest letters)

Generator registry resolves by (artifact type, output format): 8 registered combinations across `CV`, `RESUME`, `COVER_LETTER`, `INTEREST_LETTER`.

### Frontend Workflow Redesign

React + Vite + Tailwind single-page application with a redesigned tailoring workflow.

- Source profile browser (summary, experience, skills, education, certifications)
- Job description input with CV / Interest Letter generation
- Tailored document preview and DOCX download
- Optimization status banner, metric cards, job match analysis, and AI recommendations panel

### Runtime Configuration Subsystem

`.env`-based runtime configuration with startup validation and a visible configuration banner.

- `python-dotenv` load on backend startup (explicit path, not CWD-dependent)
- Fail-fast validation: `LLM_PROVIDER`, `OLLAMA_MODEL` (ollama) / `OPENAI_API_KEY` (openai)
- Startup banner reports environment, provider, model, key presence (never the key itself), and backend version
- No implicit provider fallback; missing configuration aborts startup with a clear message

### Local LLM (Ollama) Integration

Local-first LLM integration for the acquisition and tailoring pipelines.

- `OllamaLLMExtractor` for DOCX import; `LLM_PROVIDER=ollama` with `OLLAMA_HOST`/`OLLAMA_MODEL`
- OpenAI provider available when configured (`OPENAI_API_KEY`)
- JSON parser hardening for trailing-comma output from local models

## Known Limitations Deferred to Platform Beta

- **Evidence model not populated**: the canonical profile currently carries no `evidence` items or `evidenceRefs`. The optimization layer correctly reports zero ADD recommendations until the evidence model is introduced in Platform Beta - this is correct behavior, not a defect.
- **LLM-powered CV tailoring disabled by default**: `CV_LLM_ENABLED=false`; CVs are generated deterministically unless explicitly enabled.
- **Temporary port workaround**: the Vite dev proxy targets port 8001 (8000 has a stale socket on the dev machine).
- **CLI entry point** remains a thin shell over the library; the web frontend is the primary delivery surface for Platform Alpha.
