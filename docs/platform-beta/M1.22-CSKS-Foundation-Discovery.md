## 4. Query/Answer Architecture Options

### 4.1 Option A: Deterministic Search + Metadata Index (Recommended)

**Approach**: Build a structured knowledge graph (KG) from all sources, query via graph traversal + faceted search.

| Pros | Cons |
|---|---|
| 100% deterministic, reproducible | Requires upfront schema/model design |
| Aligns with CareerOS philosophy (Reasoning Before Generation) | Initial indexing effort |
| No LLM hallucination risk | Must maintain index freshness |
| Leverages existing CareerOS KG/Reasoning patterns | |
| Explainable answers (graph paths) | |
| Can answer "why" via traceability | |

**Architecture**:
```
Sources (code, docs, configs) → Extractor → CSKS KnowledgeGraph
                                              ↓
                                  Query Engine (graph traversal + filters)
                                              ↓
                                  Answer Formatter (structured + citations)
```

### 4.2 Option B: Metadata Index + LLM Augmentation (RAG-lite)

**Approach**: Build metadata index (files, symbols, summaries), retrieve relevant chunks, feed to LLM for answer synthesis.

| Pros | Cons |
|---|---|
| Handles natural language queries well | LLM may hallucinate |
| Flexible query phrasing | Less deterministic |
| Can synthesize across sources | Requires LLM provider |
| Lower upfront modeling | Contradicts "Reasoning Before Generation" |

**Verdict**: Only as enhancement layer on top of Option A, never as primary.

### 4.3 Option C: Hybrid (Deterministic Core + LLM Formatting)

**Approach**: Deterministic CSKS KG answers the query, optional LLM only formats the response.

| Pros | Cons |
|---|---|
| Best of both worlds | Adds complexity |
| Preserves determinism of facts | LLM only for presentation |
| Aligns with manifesto | |

**Recommendation**: **Option A as foundation, Option C as future enhancement**. Start with pure deterministic index.

### Core Design Decisions

| Decision | Rationale |
|---|---|
| **Pure deterministic** | Aligns with Manifesto "Reasoning Before Generation"; no LLM in critical path |
| **Graph-based** | Leverages existing CareerOS KG patterns; natural for dependencies/flows |
| **Incremental file-based index** | No external DB; fits repo-centric workflow; git-aware |
| **Same KG infrastructure** | Reuses `careeros/knowledge/` patterns; consistent |
| **Query = traversal + filters** | Simple, explainable, fast (<100ms) |
| **Citations mandatory** | Every answer traces to source file/line |
| **CLI + API dual interface** | Serves both developer tools and automation agents |
