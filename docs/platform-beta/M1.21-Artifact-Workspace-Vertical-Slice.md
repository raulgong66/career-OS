# M1.21 — Artifact Workspace Vertical Slice

## Objective

A user can open the Resume Generation workspace, select a profile, browse all artifacts for that profile, generate a new artifact from an available template, preview the artifact, export it, and return to the Home page.

This milestone delivers a complete user-visible vertical slice of the Artifact Workspace: frontend presentation, transport-only API surface, artifact domain orchestration, and artifact lifecycle behavior for generation, preview, and export.

## User Workflow

1. The user clicks the Resume Generation card on the Home page.
2. The system navigates to the Artifact Workspace.
3. The user selects an existing canonical profile from the available profile list.
4. The frontend retrieves the selected profile summary and the profile's existing artifacts.
5. The user browses existing artifacts for the profile.
6. The user chooses an available artifact template and requests artifact generation.
7. The frontend calls the backend to generate the artifact from the selected template.
8. The backend delegates generation, template selection, freshness evaluation, and export handling to the artifact domain.
9. The user previews the generated artifact in the workspace.
10. The user exports the artifact through the supported export path.
11. The user can return to the Home page from the workspace.

## Architecture

### Frontend

- Presentation only.
- Allows profile selection and artifact selection.
- Displays existing artifacts for the selected profile.
- Renders artifact preview using backend-supplied payloads.
- Invokes backend endpoints for artifact generation, preview, export, and profile/ artifact retrieval.
- Does not implement artifact business rules, template selection heuristics, freshness evaluation, or export logic.

### API

- Transport only.
- Validates request payloads and path parameters.
- Maps domain objects to frontend DTOs.
- Delegates artifact generation, template selection, freshness evaluation, export generation, and artifact lifecycle decisions to the Artifact Domain.
- Returns only transport-safe payloads and errors.
- Does not implement export or artifact transformation logic.

### Artifact Domain

- Owns artifact generation from canonical profile data.
- Selects and applies templates based on available template IDs.
- Evaluates artifact freshness and whether regeneration is required.
- Generates artifact export content through the established export pipeline.
- Owns artifact lifecycle state and behavior, including artifact metadata, generation status, and export readiness.
- Remains the only place for artifact business logic.

Business logic belongs in the domain, never in the API or frontend.

## Architectural Constraints

- The Canonical Profile remains the single source of truth.
- The existing Artifact Registry remains authoritative for available artifact templates and definitions.
- No AI provider dependencies are introduced in this milestone.
- No persistence redesign is performed.
- No frontend business logic is added beyond presentation and interaction orchestration.
- No report or export logic is implemented in the API.
- Module boundaries must remain consistent with the Platform Beta architecture: Core / Artifact Domain / API / Frontend.

## Acceptance Criteria

✓ Resume Generation card opens a dedicated Artifact Workspace.

✓ Profile selection works and displays the selected profile's artifacts.

✓ Existing artifacts are displayed in the workspace.

✓ New artifacts can be generated from available templates.

✓ Artifact preview works using backend-provided payloads.

✓ Artifact export works through the supported path.

✓ Frontend remains presentation-only.

✓ API remains transport-only.

✓ Domain owns all artifact business logic.

✓ Existing functionality remains unchanged.

## Out of Scope

- Version history.
- Artifact comparison.
- Collaboration.
- AI-assisted editing.
- Persistence redesign.
- New template system.
- PDF redesign unless already supported by the current export pipeline.

## Deliverables

### Frontend

- Artifact Workspace page accessible from the Resume Generation card.
- Profile selection control and artifact browser UI.
- Artifact preview rendering component.
- Navigation back to the Home page.
- Integration with `ProfileService` and `ArtifactService`/`InterviewService`-style transport clients.

### API

- Transport-only endpoints for artifact listing, generation, preview, export, and profile retrieval.
- Request validation and error handling.
- DTO mapping for profile summaries, artifacts, preview payloads, and export responses.

### Domain

- Artifact generation service that consumes canonical profile data and template metadata.
- Template selection and freshness evaluation logic.
- Export generation pipeline that produces preview and exportable artifact content.
- Lifecycle handling for newly generated artifacts and existing artifact refresh.

### Tests

- Frontend integration tests for workflow navigation, profile selection, artifact browsing, generation, preview, and export.
- API contract tests for transport behavior, request validation, and error responses.
- Domain unit tests for artifact generation, template selection, freshness evaluation, and export payloads.
- Regression tests ensuring no canonical profile mutation during artifact generation.
