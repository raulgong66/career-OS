# M1.19 — Interview Simulation Vertical Slice

## Objective

A user can complete a full interview simulation session and receive a deterministic summary report driven by the Canonical Professional Profile.

The milestone delivers a complete vertical slice of the Interview Simulation capability: runtime session orchestration, deterministic answer evaluation, service-facing API transport, and UI workflow for rehearsal and review.

## User Journey

1. A user selects or loads an existing canonical profile and starts a new interview simulation session.
2. The system initializes a new interview session from a validated `InterviewPlan` without modifying the canonical profile.
3. The user answers the current interview question and submits the answer.
4. The session advances to the next question, applying deterministic session lifecycle rules.
5. The user completes all questions or ends the session.
6. The system generates a deterministic interview summary report with evaluation signals, evidence alignment, and recommended next steps.
7. The user reviews the report in the frontend.

## Functional Requirements

- The user can start a new interview session from a canonical `InterviewPlan`.
- The user can submit answers for active questions.
- The user can move the session forward question-by-question.
- The user can pause and resume a session without losing runtime state.
- The user can retrieve the current session state at any point.
- The user can request and receive a session summary report after completion.
- The session report includes evaluation findings, evidence references, and advisory feedback signals.
- The system preserves canonical evidence references by stored `{id,type}` links.

## Backend / Domain Requirements

- Implement Interview Simulation as a Core consumer module independent from API and frontend.
- The Interview Simulation domain must remain separate from transport and presentation.
- The canonical profile remains the source of career data; runtime session objects only reference canonical knowledge.
- Session objects must not contain duplicated profile content or mutate the canonical profile.
- The module must support the explicit session lifecycle in ADR-007: `Draft`, `Ready`, `InProgress`, `Paused`, `Completed`, `Reviewed`, `Archived`.
- Session state may be serialized for transport, but not persisted by this milestone.
- The deterministic answer evaluation engine must validate answers, evidence references, claim alignment, and structure without provider-specific AI dependencies.
- Report generation must aggregate evaluation summaries and evidence alignment without adding AI-generated correctness judgments.
- All domain-layer evaluation and session orchestration must be provider-agnostic and free of AI SDK dependencies.

## API Requirements

- Expose a thin interview session API surface aligned with the design proposal:
  - `POST /interviews/sessions`
  - `POST /interviews/sessions/{id}/answers`
  - `POST /interviews/sessions/{id}/next`
  - `POST /interviews/sessions/{id}/pause`
  - `POST /interviews/sessions/{id}/resume`
  - `GET /interviews/sessions/{id}`
  - `GET /interviews/sessions/{id}/report`
- The API layer must remain transport-only and delegate deterministic logic to the Interview Simulation domain.
- API responses must include canonical reference IDs, session metadata, question state, answer evaluation signals, and summary report payloads.
- The API must omit internal runtime-only fields such as transient engine state, internal event queues, or temporary UI artifacts.
- The API request/response contract must preserve explicit evidence references as `{id,type}` and not serialize profile fragments.

## Frontend Requirements

- Provide a user workflow for starting, answering, advancing, pausing, resuming, and completing a session.
- Render the interview question instance, answer input, and session progress clearly.
- Display the deterministic summary report after completion, including evaluation signals, evidence alignment, and recommended next steps.
- The frontend must consume API-provided payloads and must not implement evaluation or report assembly logic.
- The frontend may present advisory language, but that language must derive only from domain-supplied feedback signals.

## Explicit Out-of-Scope Items

- No persistence layer implementation for interview sessions or reports.
- No AI provider-specific integration or vendor SDK dependencies.
- No canonical profile mutation or profile import logic.
- No interview question generation changes beyond the existing `InterviewPlan` contract.
- No advanced AI feedback narrative generation.
- No multi-user collaboration, session sharing, or analytics dashboards.
- No document export beyond the summary report view.

## Architecture Constraints

- Preserve the canonical profile as the single source of career data.
- Keep Interview Simulation domain independent from API and frontend.
- Use ADR-007 session lifecycle and runtime object boundaries.
- Do not introduce persistence or provider-specific AI dependencies in this milestone.
- Maintain strict dependency flow: Core → Interview Simulation → API → Frontend.
- Session state may reference canonical knowledge only via ADR-002 evidence links.
- Deterministic evaluation must be implemented in the Interview Simulation module, not in API or frontend.

## Acceptance Criteria

- A new interview session can be created from a canonical `InterviewPlan`.
- Answers can be submitted and accepted for the active question.
- The session can advance to the next question and complete deterministically.
- Paused sessions can resume and preserve runtime state.
- A finished session produces a deterministic summary report with evaluation and evidence alignment.
- The API routes are implemented and delegate session operations to the Interview Simulation domain.
- The frontend renders the session workflow and report using API payloads only.
- No canonical profile data is mutated during session execution.
- No persistence layer is added for session state or reports.
- No AI provider-specific dependencies are introduced.

## Testing Requirements

- Unit tests for Interview Simulation session lifecycle transitions and session state updates.
- Unit tests for deterministic answer evaluation rules, evidence validation, and summary generation.
- API contract tests for session creation, answer submission, next-step progression, pause/resume, state retrieval, and report retrieval.
- Frontend integration tests for the session workflow and summary report rendering.
- Regression tests ensuring canonical evidence references are preserved as `{id,type}` and profile content is never duplicated in session state.
- Architecture compliance tests verifying the simulation module has no direct dependency on AI provider SDKs or persistence.

## Milestone Summary

M1.19 delivers a vertical slice of Interview Simulation as a visible product capability: a complete interview session workflow from start through completion, with deterministic evaluation and a summary report, while preserving the canonical profile and respecting ADR-007 boundaries.
