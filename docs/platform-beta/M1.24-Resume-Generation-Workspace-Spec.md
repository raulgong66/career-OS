## 1. Scope

This specification defines the evolution of the existing Resume Generation subsystem into a **Resume Generation Workspace** — a deterministic, profile-centric environment integrating profile quality analysis, unified recommendations, resolution workflow, template preview, artifact versioning, and health scoring.

**In Scope:**
- Profile Quality Engine (Core module)
- Unified Recommendation API + Model
- Workspace UI evolution (Frontend Module)
- Template Preview + Artifact Versioning
- REST API extensions (additive)
- CLI extensions (additive)
- CSKS query integration

**Out of Scope (Future Milestones):**
- LLM-powered formatting layer (M1.25)
- Incremental indexing (M1.26)
- Background staleness jobs
- Multi-profile comparison
- PDF export

## 3. Profile Quality Engine (Core Module)

### 3.1 Module Structure

```
careeros/
  profile_quality/
    __init__.py          # exports: ProfileQualityEngine, ProfileQualityReport,
                         #          HealthDimension, Finding, Citation, run_profile_quality
    engine.py            # ProfileQualityEngine class (facade — orchestration only)
    dimensions.py        # 8 pure dimension calculator functions (pure functions on profile dict)
    report.py            # Dataclasses: ProfileQualityReport, DimensionScore, Finding, Citation
    cli.py               # profile-health, improvement-queue commands
```

> **M1.24.0 Clarification:** `careeros/profile_quality/` is a **facade module**. Its `engine.py` does not implement reasoning or scoring algorithms — it composes the existing `careeros.reasoning` and `careeros.resolution` packages and aggregates their outputs. `dimensions.py` contains only **pure functions** that take a profile dict and return a dimension score; these functions may consult existing utilities (`TECHNOLOGY_KEYWORDS`, `is_measurable`, etc.) but must not introduce new business rules.

### 3.1.1 Strict Profile-Centric Scope

`ProfileQualityEngine` operates **only** on the Canonical Profile (single source of truth, per ADR-004).

**MUST:**
- Evaluate canonical profiles (read-only)
- Generate deterministic findings via the existing Reasoning Engine
- Generate deterministic recommendations via the existing Resolution Engine for the 4 resolvable rules
- Generate profile health scores by composing 8 dimension calculators over reasoning findings

**MUST NOT:**
- Depend on Tailoring or any Tailoring-specific DTO
- Depend on Job Descriptions or any CVOptimizer-internal scoring
- Depend on Interview Intelligence or its evaluation domain
- Import any consumer module (Workspace, Tailoring, Interview, CSKS, CLI) — consumers depend on ProfileQualityEngine, never the reverse
- Maintain a duplicate copy of the canonical Profile or knowledge graph
- Introduce a second rule registry or parallel engine pipeline

The dependency graph is **strictly one-directional**:

```
Reasoning Engine ─┐
Resolution Engine ─┼──► ProfileQualityEngine ──► Consumers (Workspace, Tailoring, Interview, CSKS, CLI, API)
EvidenceSelector ─┘
```

`ProfileQualityEngine` reuses upstream capabilities. Consumers consume `ProfileQualityEngine`. No cycles.

### 3.6 Health Score Formula

```
health_score = round( Σ( dimension_score[d] × DIMENSION_WEIGHTS[d] ) × 100 )
```

**Determinism Guarantee:** Same profile dict → identical health_score, dimension_scores, findings, citations. No randomness, no timestamps in calculations, no external state.

## 6. Template Preview Specification

> **M1.24.0 Architectural Clarification:**
> **Preview is render-only. It is the fastest path in the Resume Workspace and must never have side effects.**

### 6.0 Preview Contract (Mandatory)

The Template Preview endpoint (`POST /artifact-templates/{template_id}/preview`) and the `ArtifactTemplate.preview(profile)` protocol method MUST obey the following guarantees:

| Property | Required Behavior |
|---|---|
| **Read-only** | Preview MUST NOT write to any persistent storage |
| **No side effects** | No I/O beyond returning rendered markdown/bytes |
| **No artifact persistence** | Preview MUST NOT create an artifact record, even temporarily |
| **No profile mutation** | Preview MUST NOT modify the Canonical Profile |
| **No exports** | Preview MUST NOT trigger DOCX export, file download, or external services |
| **No version creation** | Preview MUST NOT create an artifact version entry |
| **No tailoring context** | Preview MUST NOT require or accept a Job Description |
| **No background processing** | Preview is synchronous; no queues, workers, or async jobs |
| **Deterministic** | Same profile + same template → identical preview output |
| **Fastest path** | Preview MUST skip reasoning re-run, JD processing, and version writes |

Preview results may be cached per `(template_id, profile_version)` tuple; cache is invalidated by the Resolution Engine's profile-mutation signal. Preview **cannot** be used to satisfy an export request — an explicit Create + Generate + Export flow is required to produce an artifact.

### 6.1 Protocol Extension


### 6.2 Default Implementation

```python
# careeros/artifact_templates.py - in StandardCVTemplate, StandardInterestLetterTemplate

def preview(self, profile: dict[str, Any]) -> str:
    from careeros.export_contract import ExportContractBuilder, EvidenceSelector
    from careeros.generators import default_generator_registry
    from careeros import SchemaLoader
    
    # Build minimal contract for preview (no artifact ID yet)
    schema_loader = SchemaLoader()
    builder = ExportContractBuilder(schema_loader)
    
    # Create a virtual artifact for preview
    virtual_artifact = self.build(profile, title="Preview")
    
    # Build contract (validate=False for speed, no reasoning re-run)
    contract = builder.build(
        profile, 
        virtual_artifact["id"], 
        validate=False,
        reasoning=None  # Skip reasoning for preview speed
    )
    
    # Select evidence (no target context filtering for preview)
    selected = EvidenceSelector().select(contract)
    
    # Generate
    registry = default_generator_registry()
    generator = registry.resolve(self.artifact_type, "markdown")
    return generator.generate(selected)
```

## 7. Artifact Versioning Specification

> **M1.24.0 Architectural Clarification:**
> **Versioning belongs to generated artifacts and Resume Workspace history. The Canonical Profile remains the single source of truth and is NOT versioned by this milestone.**

### 7.0 Versioning Scope (Artifacts Only — Profile Stays Unversioned)

| Concern | Owner |
|---|---|
| **Canonical Profile history** | Profile Repository (`careeros.profile_repository`) — staging/canonical/archived states; **not modified by versioning** |
| **Artifact version history** | Artifact record, under `extensions._versions` — created by Workspace only |
| **Workspace history (preview cache, improvement-queue cache)** | Workspace-local cache — invalidates on profile mutation |

Explicit guarantees:

1. **ProfileQualityEngine MUST NOT version profiles.** It reads the canonical profile and emits a report; it does not write history.
2. **Artifact history MUST NOT mutate Canonical Profile history.** When an artifact is regenerated, the new version entry references the existing `sourceRefs`; it does not snapshot the profile.
3. **Profile mutation flow remains Resolution → Profile Repository.** Resolution continues to mutate the canonical profile in place; the Workspace observes the change via invalidation, not via per-version diffs.
4. **Preview cache invalidation hooks into Resolution Engine's existing staleness signal** (`_mark_affected_artifacts_stale()` and the equivalent profile-mutation hook added by this milestone). No new version mechanism is introduced for profiles.
5. **CSKS query layer remains the authoritative surface for "what changed in my profile?"** Versioning queries apply to artifacts only.

### 7.1 Version Storage

```json
  "id": "artifact-456",
```

### 7.2 Versioning Rules

| Event | Version Action |
|---|---|
| `POST /profiles/{id}/artifacts` (create) | Create v1, status=current |
| `POST /profiles/{id}/artifacts/{aid}/regenerate` | Create v{N+1}, status=current, previous→stale |
| `POST /profiles/{id}/resolve` (affects artifact sources) | Mark affected artifacts stale; next regenerate creates new version |
| Manual archive | Create v{N+1}, status=archived |

## 12. Risks and Mitigations

| Risk | Probability | Impact | Mitigation |
|---|---|---|---|
| Profile Quality Engine performance on large profiles | Medium | Low | Profile < 100KB typical; 8 dimensions × pure functions < 10ms; cache by `profile_version` |
| Recommendation deduplication edge cases | Low | Medium | Comprehensive unit tests for `(rule_id, element_id)` key; prefer profile_quality on conflict |
| Frontend component extraction from TailoringPage | Medium | Medium | Incremental: extract `RecommendationCard` first, verify Tailoring unchanged, then `ResolutionPanel` |
| Template Preview speed (generator re-run) | Low | Low | Skip reasoning for preview; cache rendered markdown per `(template_id, profile_version)` |
| Artifact version storage bloat | Low | Low | Versions store only metadata + markdown_hash; full markdown not duplicated |
| Resolution mutates profile in place (no audit) | Low | High | `apply_resolution` already deep-copies `before`; extend to persist audit log in `extensions._resolution_history` |
